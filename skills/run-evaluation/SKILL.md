# 学生課題評価スキル

## 使用方法

```
@run-evaluation <student_id> <assignment_num>
```

- `student_id`: 必須。学生 ID（例：`05252633`）
- `assignment_num`: 必須。課題番号 1-5

## 処理フロー

### ステップ 1: 評価スクリプト実行

```bash
./eval/evaluate.sh <student_id> <assignment_num>
```

### ステップ 2: 結果チェック

提出が見つからない場合、またはコンパイル失敗の場合はエラーメッセージを表示して停止。

### ステップ 3: 課題要件の読み込み

`assignment/assignment<N>.qmd` を読んで要件を確認。

### ステップ 4: 学生コードの読み込み

`eval/work/<student_id>/*assignment<N>*.f90` を読んでコードを確認。

### ステップ 5: コードレビュー

要件とコードを比較し、日本語でレビュー。

### ステップ 6: 総合評価

10 点満点で評価。

## 課題別評価基準

### 課題 1: 扇形計算

**要件**:
- [ ] 標準入力から半径 r と中心角θ（度数法）を読み込む
- [ ] 扇形の面積を計算：`r²θπ/360`
- [ ] 弧の長さを計算：`rθπ/180`
- [ ] 出力形式：`Area of fan:`, `Length of arc:`

**評価ポイント**:
- 入力処理：`read(*, *) r, theta`
- 円周率の扱い：`pi = 4.0_8 * atan(1.0_8)` など
- 計算式の正確さ
- 出力フォーマット

### 課題 2: ソートアルゴリズム

**要件**:
- [ ] クイックソート、マージソート、ヒープソートのいずれかを実装
- [ ] ソート検証にパス
- [ ] 計算時間の比較出力

**評価ポイント**:
- バブルソートではないこと
- 再帰/非再帰の適切さ
- 計算量の理論値との整合性
- `my_sort` サブルーチンの実装

### 課題 3: ヒルベルト曲線

**要件**:
- [ ] 再帰的サブルーチン/関数を使用
- [ ] 座標列をファイル出力
- [ ] gnuplot でプロット可能な形式

**評価ポイント**:
- 再帰実装の正しさ
- LDR, URD, RUL, DLU の回転
- 座標値の更新ロジック
- 出力フォーマット

### 課題 4: 円周率の多倍長計算

**要件**:
- [ ] 多倍長数の加算・減算・除算を実装
- [ ] Machin 公式でπを計算
- [ ] 指定桁数を正確に計算

**評価ポイント**:
- 多倍長数の内部表現
- 筆算アルゴリズムの実装
- 計算桁数の正確さ
- 出力フォーマット（10 桁区切り）

### 課題 5: 次元付き物理量モジュール

**要件**:
- [ ] `quantity_t` 型（値 + 次元配列）
- [ ] `quantity(val, unit_str)` 関数
- [ ] 演算子：`+`, `-`, `*`, `/`
- [ ] 次元不一致の処理（NaN を返す）
- [ ] テストスイートにパス

**評価ポイント**:
- 単位文字列のパース（`m`, `kg`, `s`, `m/s`, `m^2` など）
- 次元配列の扱い `[length, mass, time]`
- 演算子オーバーロード
- エラーハンドリング

## Fortran スタイルチェック

- [ ] `implicit none` を使用
- [ ] `intent(inout)` を適切に使用
- [ ] 2 スペースインデント
- [ ] 変数名が分かりやすい
- [ ] サブルーチン/関数の名前が適切

---

## 採点基準（10 点満点）

| 点数 | 基準 |
|------|------|
| **9-10** | 完全実装、スタイル完璧、改善点ほぼなし |
| **7-8** | 機能は完全、minor な改善点あり |
| **5-6** | 主要機能は OK、改善余地あり |
| **3-4** | 一部実装のみ、大きな改善が必要 |
| **1-2** | コンパイルのみ、機能不足 |
| **0** | 提出なし/コンパイル失敗 |

---

## 注意事項

- 提出が見つからない場合はエラーメッセージを表示して停止
- `eval/work/` ディレクトリはクリーンアップしない
- テンプレートファイル（`assignment/template/`）は参照しない
- コードの引用は短く、要点を押さえる
- 日本語で報告（技術用語は英語のまま可）
